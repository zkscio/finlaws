## このリポジトリが解く問題

金融規制の条文は、法律・政令・内閣府令・命令が何層にも分かれており、e-Gov の HTML を毎回開いて「第何条のどこか」を探すと遅いです。LLM に丸ごと食わせると、1 本の法律だけでコンテキストを埋めます。

finlaws は次の 3 点だけをやります。

1. **1 法令 = 1 フォルダ**。ルートに長い全文ファイルを並べない。
2. **全文と章を同居**させる。`00_全文.md` で通読し、`NN_第○章_….md` でピンポイント参照する。
3. **機械可読な索引**を置く。`INDEX.md` は法令名・種別・e-Gov `law_id`・フォルダパスを持つ。

正本の代替ではありません。検索と参照のレイヤです。

```bash
git clone https://github.com/zkscio/finlaws.git
cd finlaws
```

| やりたいこと | 開く場所 |
|---|---|
| 何が入っているか見る | [`INDEX.md`](./INDEX.md) 冒頭の法令一覧 |
| 資金決済法を通読する | [`法律/01_資金決済法`](./法律/01_資金決済法/00_全文.md) |
| 暗号資産の章だけ読む | [`法律/01_資金決済法`](./法律/01_資金決済法/05_第三章の三_暗号資産.md) |
| ある法令の章構成を見る | そのフォルダの `_INDEX.md` |
| キーワード横断 | 下の `grep` 例 |

```bash
# 資金決済法の第2条
grep -n "第2条" 法律/01_資金決済法/

# 電子決済手段を全法令から探す
grep -rn "電子決済手段" --include='*.md' .

# 暗号資産交換業
grep -rn "暗号資産交換業" --include='*.md' .
```

e-Gov の正本に戻るときは、`INDEX.md` の `law_id` を使います。

```
https://laws.e-gov.go.jp/law/{law_id}
```

例: 資金決済法は `421AC0000000059` → [laws.e-gov.go.jp/law/421AC0000000059](https://laws.e-gov.go.jp/law/421AC0000000059)

## ディレクトリの見方

ルートは案内・索引・品質報告と、種別ごとの親フォルダだけです。作業ログやローカルパスは入れていません。

```
finlaws/
├── README.md                 この案内
├── INDEX.md                  全法令一覧 + 章分割インデックス
├── COVERAGE.md               金融庁所管 470 件を基準にした網羅レポート
├── CHANGELOG.md              版ごとの変更履歴
├── LICENSE                   MIT（構成・整理作業。条文本文は法令）
│
├── 法律/                     法律（103）
│   └── 01_資金決済法/
│       ├── 00_全文.md        e-Gov から落とした条文全文
│       ├── 00_序章・目次.md
│       ├── 01_第一章_総則.md
│       ├── 02_第二章_前払式支払手段.md
│       ├── 03_第三章_資金移動.md
│       ├── 04_第三章の二_電子決済手段等.md
│       ├── 05_第三章の三_暗号資産.md
│       ├── 06_第三章の四_電子決済手段・暗号資産サービス仲介業.md
│       ├── …章・雑則・罰則
│       └── _INDEX.md         この法令だけの章一覧
│
├── 政令/                     政令（100）
├── 内閣府令/                 内閣府令（73）
├── 府省令/                   府省令（58）
├── 命令/                     命令（99）
├── 規則/                     規則（33）
└── 省令/                     省令（3）
```

番号は収録順です。若い番号ほど、資金決済・AML・銀行・金商など参照頻度の高い法律が集まっています。

## AI / LLM での使い方

トークンを節約し、条文の取り違えを減らすための推奨順です。

1. **まず `INDEX.md` で法令を特定する。** 通称（資金決済法）と正式名、`law_id` が並んでいます。
2. **その法令の `_INDEX.md` で章を特定する。** 全文を最初から読まない。
3. **必要な章ファイルだけをコンテキストに入れる。** 例: 暗号資産なら `法律/01_資金決済法`。
4. **条番号の根拠が要るときだけ `00_全文.md` を当たる。**
5. **回答に e-Gov `law_id` とファイルパスを残す。** 後から正本照合できます。

やってはいけないこと:

- ルート直下に全文が並んでいる前提で読む（現行構造では各フォルダの `00_全文.md`）
- 府令と法律を同じファイルだと思って引用する
- このコピーだけを根拠に「現行法はこうだ」と断定する

プロンプトの型:

```
日本の資金決済法について、暗号資産交換業の定義を条文に即して整理してください。
一次資料は 01_資金決済法/05_第三章の三_暗号資産.md です。
条番号を明示し、断定できない改正の有無は e-Gov law_id 421AC0000000059 を見よと書いてください。
```

## ファイル規約

| ファイル | 意味 |
|---|---|
| `00_全文.md` | その法令の条文全文。分割前の原文 |
| `00_序章・目次.md` | タイトル・目次がある場合 |
| `NN_第○章_名称.md` | 章・節単位の分割。LLM の入力単位 |
| `_INDEX.md` | その法令フォルダ内の目次 |
| `INDEX.md` | リポジトリ全体の法令一覧 + 章インデックス |
| `COVERAGE.md` | 金融庁 470 件との突合・品質検証 |
| `CHANGELOG.md` | 人が読む版履歴 |

共通ルール:

- 拡張子は `.md` のみ。Excel やバイナリの条文は置かない。
- 文字コードは **UTF-8 with BOM**。BOM なしは Telegram / 一部ビューアで化ける。
- 公開ツリーにローカル絶対パス、トークン、秘密鍵を書かない。
- フォルダ名は `{番号}_{短い法令名}`。通称がある法律は通称を優先（`法律/01_資金決済法`）。

## 更新の入れ方

1. e-Gov の現在施行版を取得する（公式 API / 法令本文）。
2. `00_全文.md` を BOM 付き UTF-8 で書く。
3. 章・節・附則に分割し、フォルダ内 `_INDEX.md` を更新する。
4. ルート `INDEX.md` の法令一覧行を追加または修正する。
5. `COVERAGE.md` の件数と未収録表を更新する。
6. `CHANGELOG.md` に日付・件数・破壊的変更を書く。
7. 公開前にパス漏洩と BOM を再検査する。

改正のたびに自動追従する仕組みではありません。スナップショットです。日付は README 先頭のバッジと CHANGELOG を見てください。
